# Study II run handoff

1. Clone the repository on the target computer. Copy the three MEISD source files listed in `DATA_LAYOUT.md` to `data/source/meisd/` and verify their hashes. Run the `audit-data` and `prepare-meisd` commands in the main README. Download and prepare BRIGHTER at the pinned revision. Check the prepared manifests: MEISD 1,378/118/118 with `prepared_segment=start`; BRIGHTER 2,753/115/2,765 with the official test IDs and labels intact.
2. Install a PyTorch build compatible with the GPU. Run `python -m pytest -q` and a small smoke run on both prepared datasets. Verify `pip check`. The smoke model is randomly initialised and its scores have no scientific interpretation.
3. Generate the primary matrices on the target computer using the README commands. Configurations include absolute paths to prepared data and relative output paths, so run the CLI from the repository root. Keep `matrix.json` and individual configs with the results. The primary scope is 50 MEISD and 30 BRIGHTER runs; optional backbones and legacy architectures use separate matrix directories.
4. Time short **real-backbone** pilots for the four main architectures on both datasets. Record seconds per optimiser step, diagnostic time, peak GPU memory, truncation rate, and checkpoint size. Estimate total time, storage and retry margin before starting the full matrix. The earlier CPU pilot is not a GPU runtime estimate.
5. Run and archive each matrix. The runner skips completed, configuration-matching runs and stops on an incomplete or mismatched directory. Review development results and the complete run manifests. Evaluate the held-out test once for the frozen matrix. Use the prespecified comparisons for interpretation.
6. Generate the final report with `att report --runs outputs --output outputs/report-study2 --split test`. Review per-seed and paired STL differences, conditional pair-to-triple differences, majority baselines, per-class scores, joint emotion-intensity metrics, confusion matrices, losses, gradients, routing, and resource use. Archive `outputs/` separately from Git.

The automatic checks establish file alignment, reproducible partitioning and pipeline behaviour. They do not establish semantic validity of inherited labels. The source-label construction and a sample audit of generated examples must be documented in the dissertation.
