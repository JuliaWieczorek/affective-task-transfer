# Study II run handoff

1. Clone the repository on the target computer. Copy the three MEISD source files listed in `DATA_LAYOUT.md` to `data/source/meisd/` and verify their hashes. Run the `audit-data` and `prepare-meisd` commands in the main README. Download and prepare BRIGHTER at the pinned revision. Check the prepared manifests: MEISD 1,378/118/118 with `prepared_segment=start`; BRIGHTER 2,753/115/2,765 with the official test IDs and labels intact.
2. Install a PyTorch build compatible with the GPU. Run `python -m pytest -q` and a small smoke run on both prepared datasets. Verify `pip check`. The smoke model is randomly initialised and its scores have no scientific interpretation.
3. Generate the primary matrices on the target computer using the README commands. Configurations include absolute paths to prepared data and relative output paths, so run the CLI from the repository root. Keep `matrix.json` and individual configs with the results. The primary scope is 50 MEISD and 30 BRIGHTER runs; optional backbones and legacy architectures use separate matrix directories.
4. Time **real-backbone, 192-token** pilots for the four main architectures on both datasets. Record full-epoch time, diagnostic time, peak GPU memory, truncation rate, transient resumable-checkpoint size and final checkpoint size. Estimate total time, storage and retry margin before starting the full matrix. The earlier 128-token GPU pilot is a reference only; it cannot time the new protocol. Follow `PRE_RUN_CHECKLIST_2026-10-02.md` for executable commands and stop/go criteria.
5. Run and archive each matrix. The runner prints completed/total runs and a rough ETA after the first timed run; the current estimate is also in `<matrix-directory>/progress/status.json`. The estimate averages runs completed in that invocation and can shift across architectures. The runner verifies completed checkpoints and resumes a matching interrupted run from the last completed epoch, redoing a partly completed epoch. Review development results and all run manifests. Evaluate the held-out test once for the frozen, complete matrix. Test result and prediction hashes are stored in each run manifest.
6. Generate the final report with `att report --matrices outputs/matrix-meisd-study2-2026-10-02/matrix.json outputs/matrix-brighter-study2-2026-10-02/matrix.json --expected-runs 80 --output outputs/report-study2 --split test` (substitute the actual matrix paths). The report rejects incomplete matrices and changed artifacts. Review per-seed and paired STL differences, direct architecture contrasts with their resource costs, conditional pair-to-triple differences, majority baselines, per-class scores, joint emotion-intensity metrics, confusion matrices, losses, gradients and routing. Archive `outputs/` separately from Git.

The automatic checks establish file alignment, reproducible partitioning and pipeline behaviour. They do not establish semantic validity of inherited labels. Document the source-label construction and this limitation in the dissertation.
